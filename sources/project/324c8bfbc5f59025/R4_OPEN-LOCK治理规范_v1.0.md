# R4｜OPEN-LOCK治理规范 v1.0
## ——Phase 5

# 1. 定义

`OPEN-LOCKED`不是“尚未研究”，而是：

> **已经完成当前证据条件下的审查；现有材料不足以唯一决定该接口，因此把“不确定性本身”冻结为结论。**

它与以下状态严格区分：

- `PENDING`：工作尚未做完；
- `WATCH`：尚有必须继续裁定的风险；
- `C`：当前正文/施工的具体选择；
- `PC`：工作回次安置；
- `OPEN-LOCKED`：证据边界已审完，禁止下游把开放项写硬。

# 2. OPEN-LOCK四条纪律

1. **当前C可以继续写，但必须可撤销。**
2. **正文已经采用某方案，不构成证据。**
3. **历史可行性只证明“可以发生”，不证明“曹稿就是如此”。**
4. **没有新上游证据，不得仅因文学上更顺而解除OPEN-LOCK。**

# 3. 重新打开条件

只有以下情况可把`OPEN-LOCKED`重新转为`LOCK-PENDING-REGRESSION`：

- 新发现更早、更直接、可复核的Witness；
- 原Witness/Provenance重新定级；
- Evidence Role / Literal Target / Placement发生上游变化；
- 新一手历史材料证明当前C机制不可行；
- 发现活动正文或过程文档已经违反该OPEN边界。

重新打开后只回归受影响链，不全盘推倒。

# 4. 引用纪律

OPEN项目在学术说明中必须使用：
- “当前采用……”
- “工作安置……”
- “一种可行实现……”
- “现证未能锁定……”

禁止使用：
- “原稿就是……”
- “脂批证明……第X回”
- “曹雪芹安排……”
- “必然……”
除非上游证据确实支持。

# 5. 对R4放行的意义

OPEN-LOCKED项目：
- **不阻止R4结束；**
- 但必须全部进入冻结表；
- Phase 6清扫时若发现OPEN被写成硬事实，则重新转A类阻断。
