# 证据角色六字段治理规范_v1.1_当前版
## ——R1：先确认“它是什么证据”，再讨论“它有多硬”

> 状态：**ACTIVE-GOVERNANCE**  
> 适用：所有80回后脂批、批者见稿语、靖藏转录、诗文伏线、工作回目、正文实施事实。  
> 本规范取代“只凭V0—V5就决定正文逐字回灌”的做法。

---

# 0. 为什么必须增加“证据角色”

此前V轴已经区分：
- N-EXACT
- S-EXACT
- SEM
- D0/D1/D2/D3

但仍发生了三个错误：

1. `凤姐扫雪拾玉`是未来场景，却被视觉上当成了回目半联；
2. `寒冬噎酸虀，雪夜围破毡`是“后数十回……等处”的生活情状，却被直接用成完整回目；
3. `对景悼颦儿`只有靖藏转录，却被误写成主本庚夹硬证。

根因不是“字没看见”，而是：

> **证据角色没有单独建模。**

---

# 1. 六字段

每条后80证据以后至少登记六个字段。

| 字段 | 必答问题 |
|---|---|
| **Witness / Provenance** | 来自哪个本、哪种批、能否直接复核？ |
| **Role** | 回目、标目、稿名、作品名、正文残语、未来对白、事件、结构、批者概括，还是弱见证？ |
| **Modality** | 批者亲见、明确断言、推测、靖藏W2、否定/撤销？ |
| **Literal Target** | 小说必须逐字、只在证据层逐字、只锁语义，还是只锁边界？ |
| **Placement** | 只知“后文”、只知“末回”、80后高概率，还是具体回次只是C？ |
| **Implementation** | 当前正文怎样兑现；这一步是否可撤销？ |

---

# 2. Witness / Provenance

| 代码 | 含义 | 权限 |
|---|---|---|
| **W1-DIRECT** | 现存可直接复核的脂本/正文批语 | 可承重，但仍须看Role/Modality |
| **W1-SEEN** | 强见证批者明言“曾见稿/正文标目” | 可高权重承重 |
| **W2-TRANSCRIPT** | 靖藏等单线转录，原本不可复核 | 只能增权，原则上不得单独制造主线 |
| **EDITORIAL** | 现代校注/整理者判断 | 研究参考，不作为原稿硬证 |

永久规则：

> **W2不能给自己制造动机。**  
> **W2 × W2 ≠ W1。**

---

# 3. Role｜证据角色

| 代码 | 角色 | 示例 |
|---|---|---|
| **TITLE-FULL** | 完整未来回目文字 | `薛宝钗借词含讽谏，王熙凤知命强英雄` |
| **TITLE-PART** | 明说正文标目但只存部分 | `花袭人有始有终` |
| **DRAFT-LABEL** | 稿名/稿件辨识名 | `狱神庙慰宝玉` |
| **CHAPTER-CALL** | 批者称“某某一回” | `悬崖撒手`、`误窃` |
| **WORK-TITLE** | 诗文/作品名称 | `十独吟` |
| **FUTURE-LINE** | 明指后文将出现的确切文字 | `落叶萧萧，寒烟漠漠` |
| **FUTURE-SPEECH** | 批者直接引述未来人物话语 | `好歹留着麝月` |
| **EVENT** | 未来情节/动作 | `凤姐扫雪拾玉`、`甄宝玉送玉` |
| **STRUCTURE** | 未来章节/层级结构 | 末回有情榜、正副再副三四副 |
| **CRITIC-DESCRIPTION** | 批者对未来文字的概括性称呼 | `警幻情榜`在正式榜名问题上的身份 |
| **W2-HINT** | 单线弱见证 | `对景悼颦儿`、`狱庙相逢`、`仗义探庵` |

---

# 4. Literal Target

以后禁止只写“N-EXACT”而不说明对象。

| Target | 含义 |
|---|---|
| **NOVEL-EXACT** | 有充分理由认为失稿正文/回目中这几个字必须出现 |
| **NAME-EXACT / POS-OPEN** | 作品/称呼的名字可以锁，但具体落在哪一回开放 |
| **SOURCE-EXACT** | 只要求证据台账准确保存批语原字；小说不必照抄 |
| **SEM** | 只锁情节/功能 |
| **BOUNDARY** | 只锁“不能再多说什么” |
| **NEG** | 明确阻止硬化 |

重要：

> **批语中的原字 ≠ 小说正文中的原字。**

---

# 5. Placement

| 级 | 含义 |
|---|---|
| **P0-FIXED** | 源证明确具体回/末回 |
| **P1-RANGE** | 只知“后文/后数十回/第64以后” |
| **P2-HIGH-PROB** | 根据现存断点，高概率在80后 |
| **PC** | 当前工程人为安置，纯C级 |

例如：

`十独吟`：
- NAME-EXACT：强
- 第64以后：强
- 80后：高概率
- 第85：C

不能再把四层合成一句“第85必须出现《十独吟》”。

---

# 6. Implementation

每个C级正文事实以后必须登记：

- 首次实体化回次；
- 是否可撤销；
- 是否已进入标题；
- 是否已成为跨回依赖；
- 若撤销，需要回归哪些文档。

这样可防止：
> **一个C方案因为写进纯读版，就自动变成后续的“事实”。**

---

# 7. T轴独立于V轴

V轴继续回答：
> “批语留下了什么字/什么事件？”

T轴只回答：
> **“这些字有没有资格作为原稿回目证据？”**

任何V3/V5事件短语都不得自动升为T0/T1。

---

# 8. 新审计顺序

以后证据回归必须按：

> **Provenance → Role → Modality → Literal Target → Placement → Implementation → Literal → Semantic → Boundary → Literary/P-Lock**

不得再从“字符串命中”直接跳到“证据兑现”。
