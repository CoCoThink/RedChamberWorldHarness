# v6交付后的执行顺序

本文件列下一阶段顺序，不把尚未执行的事项写成完成。当前研究版与旧负面、旧比较独立保留；production、stable、人工与P9均未授予。

1. 先完成本轮正常build、已提交检出的克隆复现及最终准确HEAD双版本CI。输入冻结CI仅证明读者输入版本，不代替交付CI。
2. 下一项harness工程优先处理真实world输入的作用域。先盘点renderer实际读入的事件、人物、对象、时点和消费者，给出可评审的语义投影设计与变更影响表，再实现新版本请求协议；不得仅忽略全局文件摘要或对旧请求静默改绑。治理文件已从提示词依赖分离，不等于world已完成局部化。
3. 投影须包含相关实体、时点前状态、被消费字段及可核验来源；对象交接、知识获得、制度约束与跨回前提不能因范围缩小漏出依赖。未知数据仍为UNKNOWN。必须明确全局新增相关事件、删除依赖、字段变化和投影规则升级各自怎样触发失效。先用窄范围真实写作包试点，不批量迁移20回。
4. 用变更矩阵证明行为：无关治理或无关人物修改不污染正文谱系；相关事实/事件/时间/投影规则变化使当前相容性失败；历史原字节仍有效；新增依赖经重渲染发现。兼容性不授予语义回放、审阅或生产资格。协议新增测试只检查这些行为，不能复制投影实现作预期。
5. 工程通过后，文学改动优先窄读87和93。87维持明确服毕前提，尝试恢复老人余年焦虑和不圆满冲突、减少权责说明及过整齐体贴；不恢复不明风险靠父母担责机制。93优先压缩末段交孩子、换布找针、站位。95两票TIE、97比较分歧及其他节奏建议按旧台账择取，不一律机械修改。
6. 正文或完整读集变化，追加实际作者/编辑/保管链，建立新选择器和请求。只复用完整审阅输入完全一致的旧意见；BOOK当前要求全组精确相同才复用，不宣称已有按单段局部复用。按影响范围实际分派，先冻结并等双CI，再用新上下文读者、scaffold、最多3并发、串行登记和实际失败重试。
7. 独立人工史料、全语料核证与正式文学盲评继续使用v5交接索引作为历史起点，改用实际新选中包补交接；没有意见时保持PENDING，不使用模型或字节校验冒充真人。任何stable晋升另走既有所有者准入。

本轮仍保留S2收束答话的严格解释空间、S5未决栏条件残语以及全部物件/信件/人间终局未核事项；冻结合同不原位改动。若下一版只修清晰度，另版并按实际读集重算，不以修辞清理自动继承PASS。
