2026-10-09 所有者选择：**暂不授予许可，先完成权属与许可方案**。本文件是方案，不是授权文本；不新增 LICENSE，不修改包的许可声明。

## 当前清单

[机器清单](../../data/project/rights_inventory.json)列出 363 个已登记资产的 ID、SHA、路径、类型和 origin_refs。未发现的许可字段写为 null，权属写为 NOT_DETERMINED，不能把本地保存、Git 作者名或资产登记当作授权证明。Git 提交身份只提供作者线索。

| 范围 | 本次处置 | 将来授权前须补的事实 |
|---|---|---|
| 自主 runtime、schema、测试、工具 | 保持未授权；可独立拟定代码许可 | 确认贡献人和可授权范围，识别引用或移入的第三方代码 |
| 自主说明与新增编辑卡 | 单列于代码之外，保持未授权 | 确认文档作者及所含原文引用的来源 |
| PDF、EPUB、网页抓取、档案照片 | 逐件保持原出处与已有声明，不套用未来代码许可 | 记录每一载体的原许可、权利人、授权范围与获得时间 |
| 抽取、语料、索引、校录与评审包 | 保持输入 lineage，不声明拥有全部材料权利 | 区分纯技术结果、自主编排、原文内容及第三方评审的授权 |
| 稳定复原正文、候选与本次九份短稿 | 单独的文学文本范围，保持未授权 | 决定是否公开、转载、改写、商业使用，以及署名方式 |
| 原始人类评审 | 不因登记或归档而取得再许可权 | 取得评审者对保存、匿名展示及传播的具体授权 |

底本作品、编校、注释、页面图片和现代汇编分别记录；不根据底本年代推断现代载体可任意再发布。清单是下一轮核实入口，不是法律结论。

## 供之后选择的代码方案

若所有者决定开放自主代码，可采用 [MIT 官方模板](https://opensource.org/license/mit)，限定 `src/`、`schemas/`、`tests/` 和自主工具/构建文件；另行列出排除的数据、原件、评审与文学文本。模板要求保留版权与许可声明。另一候选是 [Apache-2.0 官方文本](https://www.apache.org/licenses/LICENSE-2.0)，有明确的专利授权及再发布条款。

选择后再填写真实权利人，加入明确的适用路径清单和完整许可文本，并更新包元数据。第三方项目保持各自许可；不得用总代码许可覆盖数据目录。文学文本的公开范围另作所有者决定，不在本方案里默认选 CC 或其他许可。

## 可执行的下一次变更

在机器清单新增逐项 `rights_holder`、`license_source`、`license_text_sha256`、`permission_scope` 和 `verified_by`，原出处字段不改写。已确定授权的子集可以单独打包；其 manifest 应列出适用许可及排除项。当前 release 附件命令只准备本地材料，没有公开上传，也不产生新的许可。
