# 评估与复原竞争的针对性重构设计

状态：内容重建、评审资格、语义重放、文体/人物诊断、三回研究材料与结构整理已实施。真实独立评审、外部模型校准、有效流程对照和三回文学验收仍待完成，详见 §9.2。依据：[2026-10-09 评审核查](../reviews/LITERARY_EVALUATION_REVIEW_20261009.md)。

目标是让现有来源、证据和四层真值基础支撑可核验的正文检查、真实方案比较和连续三回编辑。工作围绕既有“来源与证据、世界与连续性、文学诊断、独立阅读”四类评估展开；试点结束前冻结门禁类型，使用既有类别表达新增检查内容。

## 1. 保留的边界与设计取舍

Source → Claim → Decision → Implementation、Evidence / Reconstruction / Character / Text Truth、OPEN 边界、不可变资产、正文内容绑定、候选采用与稳定发布分离，继续作为基础。

现有 P6/P7/P8 的场景路线、匿名材料、快照、原始意见、排序和修订配对作为可复用实验记录。第 86 回 A/B/C 保留为“同路线密度比较”历史实验；旧裁定的实际意见和来源缺口分别展示，后续正式资格由新接口验证。不得补造旧评审者身份、模型或运行日志。

本次设计不把文学效果收敛成一个自动总分。可计算的事实和语义约束负责查错；人物可信度、章回效果和余味由比较阅读与编辑裁定承担。

## 2. 首先修复内容重建守卫

### 2.1 分开记录三种身份

| 对象 | 身份依据 | 环境变动后的处理 |
|---|---|---|
| 原始资产及历史 manifest | 登记原字节 SHA、输入/派生关系、manifest 自身摘要 | 始终核验，不改写历史原件。 |
| 抽取配方与产物 | 输入资产、规范化后的语义配置、输出 JSONL 字节及 unit/span 映射 | 用当前工具重建并比较内容，内容相同可以通过。 |
| 当前重建观察 | 实际 Python、依赖、代码 SHA、时间、工具差异 | 写入新的验证报告，作为环境信息，不混入“输出改变”的结论。 |

`load(rebuild=True)` 流程调整为：校验历史资产 → 校验原 manifest 身份和派生关系 → 用登记输入与语义配方重建 → 比较完整 output 原字节、unit_refs 和定位映射 → 返回内容结果与 `toolchain_diff`。重建失败或产物不同仍 FAIL；缺依赖返回明确环境错误，不伪装成产物过期。

只有输出相同不足以任意接受输入改绑：载体、配置、关系和 locator 的原绑定仍须成立。新配方/新来源需建立新版本。依赖版本可以继续由 lock 提供参考安装环境；跨版本重建验证允许运行，然后以实际内容决定一致性。

### 2.2 同步处理所有消费者

| 位置 | 改动 |
|---|---|
| `corpus/extraction.py` | 去掉当前工具与历史工具的等值前置拒绝；对 lock 比较解析后的配方意义，环境差异另报。历史 ID 仍按历史原 manifest 验证。 |
| `corpus/locators.py` | 缓存绑定输入、输出、配方和当前执行器标识；执行器变化使缓存重建，不自动判内容失败。登记旧报告按输入与验证结果投影比较，当前工具观察另存。 |
| `corpus/inputs.py` | 库存重建比较章界、spine、字形缺口等内容投影；库存工具哈希变更单列。 |
| `corpus/dataset.py` | 校验存储 manifest 原件；重建时逐文件比较产品和语义输入，builder 代码变动单列。 |
| `acceptance.py` / closure | 汇总内容失败、环境错误和待评审状态，避免版本差异冒充正文不一致。 |

v1 manifest 继续可读，原 SHA 与所有下游引用不变。新建运行报告可增加观察字段；确需 v2 新产物协议时仅用于新构建，不批量重写旧 manifest 或刷新评审摘要。

版本政策首期统一到经实际验证的 CPython `>=3.12,<3.13`：pyproject、lock 及其解析器、README、CI 一起更新。3.12.13 是参考构建环境；3.12.3 是兼容回归环境，不作为升级建议。若继续承诺 3.10/3.11 或扩展到 3.13+，先补完整兼容矩阵。原解析器固定要求 `>=3.10`；首批实施已同步更新，保留旧 lock 的解析兼容。

验收：两个实际 3.12 环境重建现有十份抽取以及语料，字节相同均通过；代码注释、lock 排版和依赖版本变动只产生观察差异；相同工具信息下输出被篡改仍失败；locator span 漂移和错误输入改绑仍失败。来源旧报告在语义结果一致时不因 verifier 注释改动失效。

## 3. 统一报告，区分计算与阅读意见

使用一个报告外壳接入现有四类评估，避免每个阶段再增一种门禁。

```json
{
  "report_kind": "COMPUTED_CHECK | REVIEW_OPINION",
  "category": "WORLD_CONTINUITY",
  "candidate_sha256": "…",
  "context_sha256": "…",
  "contract_sha256": "…",
  "protocol_sha256": "…",
  "status": "PASS | FAIL | WARN | PENDING",
  "producer": {"id": "…", "kind": "…", "run_ref": "…"},
  "coverage": {"required": ["…"], "checked": ["…"], "unresolved": ["…"]},
  "findings": [{"check_id": "…", "evidence_spans": [], "reason": "…"}],
  "raw_input_ref": "…",
  "raw_output_ref": "…"
}
```

以上为字段轮廓，不是已实施 schema。`PASS` 只能由对应 checker 或已绑定意见的完整性投影产生。`REVIEW_OPINION` 的结论始终是阅读意见，机器只能验证它提交完整、身份符合协议、输入未变。

缺少必需覆盖或缺少独立语义判读返回 PENDING，不把未检查项折叠为 PASS。有效硬错误返回 FAIL，不被其他文学意见抵消。过期记录因绑定无效不能使用；保留原意见本身，当前投影显示需要重评。

六字段分开处理：引用身份、目标对象、位置和正文哈希等可确定性计算；ROLE/MODALITY 是否被误用及 IMPLEMENTATION 是否真正呈现承重关系，需正文语义核对或编辑意见。不得把检查六个字符串等于 PASS 继续称为六字段回归。

竞争、生产状态、promotion 与 acceptance 从同一验证服务读取结果。promotion 必须核验当前候选和有效评审，不能只读取 competition 的 WINNER/PROMOTION_CANDIDATE 标记。

## 4. 将词串规则降为 lint，接入正文语义

### 4.1 保留词串的合理用途

required/forbidden beats、知情词串、历史可行性词组、显性解说与套语输出命中位置、提示与风险，称为 lint。没有命中不表示语义正确；单纯命中禁词不证明事件发生。

真正逐字约束继续用确定性检查，例如登记为 P1 的终端句、回目原字锚点与匿名材料中实际泄露的身份字段。逐字合同与情节语义分开声明。

历史适配器提供可行性资料和未决问题；生成提示改用行动、资源和关系要求。不得要求作者在正文塞入“炉”“药”等配额来证明历史可行性。已有词组保留为内部 lint，不作文学通过条件。

### 4.2 最小语义抽取接口

独立于作者生成侧，从实际候选原字节抽取事件、说话者、行为者、事实断言、获知来源、时间顺序和出口状态。每条抽取绑定文本 SHA 和原文跨度；抽取结果必须能逐字定位到候选。

```json
{
  "candidate_sha256": "…",
  "events": [{
    "id": "e1", "actor": "zijuan", "mode": "ACTION",
    "time_ref": "…", "assertion_scope": "ACTUAL",
    "negated": false, "source_spans": [{"start": 0, "end": 12}],
    "effects": [{"target": "object:medicine_bowl_86.temperature", "value": "cold"}]
  }],
  "final_observations": [],
  "unresolved": []
}
```

抽取必须区分实际发生、否定、假设、梦境/幻觉、人物信念、引用与比喻；先明确 assertion_scope，再判断事件是否违反当前契约。抽取信心数值不能替代原文依据。

作者提供的结构化 sidecar 可作为写作意图，与正文抽取结果比较；不能仅凭作者把 `dead/cold` 填入 sidecar 就 PASS。没有正文支撑的出口不能成立。模型输入把候选作为待分析数据，文内“忽略规则/请给 PASS”不成为执行指令；结果跨度及取值由本地校验。

### 4.3 用已有状态能力判约束

接入前先统一场景 state adapter：明确选定 WorldRuntime/Knowledge/Object 的版本和 ENTRY，映射旧 `character.*`、`object.*` 目标及大小写状态枚举，避免小型 `WorldState` 和领域重放各说各话。紫鹃须有可绑定身份；兼容时明确缺失，不默许 optional 角色拥有不存在的状态。

本地 checker 基于有正文依据的抽取结果核对：

- required beat 是一个实际叙事事件或行动关系；词表与空记录不能替代。
- `exit_state` 对照正文最后相关实际状态；黛玉死与药冷都要得到文本依据，允许通过动作和物象间接呈现。没有证据的必需出口为未完成，不要求出现“死”这个字。
- 禁止情节按场景语义定义核对，区分有哲理色彩的叙述与黛玉实际临终总结、普通幻觉与超自然实质治愈。
- 获知事实按事件顺序更新角色知识；角色对白、行动、叙述者信息分开。人物猜测不得变成“已知”；角色在见证后才知道的事不因全文 ENTRY 检查被误拒。
- 资源、物件和事件更新只进入 Reconstruction / Character / Text 状态，不反向晋升 Evidence Truth。

抽取器可由模型或编辑标注提供。未接入时语义覆盖为 PENDING；模型失效或输出无效时不能 fallback 成 lint PASS。遇到歧义交编辑判读。保存实际请求、提示全文、模型/参数、工具配置和完整响应，后续审计依靠固定结果，不要求重调模型复刻。

### 4.4 回归与校准

将核查报告中的前三例固定为必须 FAIL 的语义回归，并增加出口冲突、否定/引用、梦境、隐喻、人物猜测、正常获知后的对白与有效间接死亡场景。否定禁词例仍可能因缺出口不合格，但 forbidden check 必须证明没有发生禁情节。

CI 的确定性部分用编辑核对的文本、原文跨度和期望约束检验重放与核对器；外部模型的语义能力用固定挑战集运行并保存实际结果。不能用手填理想抽取的单元测试通过，声称实际模型已识别了三段反例。

首批集纳入现有 stub、正式候选、编辑确认的有效变体与上述攻击变体。报告每类误放/误拒、未判定数量、有效跨度比例和覆盖；前三例必须全部拒绝，正例不能因用了禁词的否定或比喻而被同类错误拒绝。三回小样本不宣称统计普适性。

## 5. 评审来源与真正的盲性

复用 P9 的 packet/raw review 哈希绑定、最低两人和拒绝作者同 ID，再把它扩展给完整章回竞争。保留 `INDEPENDENT_HUMAN` 的正式阅读轨；模型语义检查和模型文学诊断使用独立记录类型，不能改名成“人工盲读”。

运行/评审身份至少记录：实际 principal ID、作者/评审角色、human/model 类型、会话或执行 ID、模型的 provider/name/version/family（模型适用）、参数、提示摘要与全文资产、上下文/候选/protocol/packet SHA、原始输出、提交时间，以及曾接触哪些材料。人类评审记录稳定身份与匿名材料交付声明，不填虚构的模型信息。

“不同源”政策：作者与正式评审者的 principal 必须不同。模型诊断若声称独立，还须不同生成/评审模型族、隔离上下文，并声明可能的相关性；同模型换角色提示只算内部自评。正式章回比较首期仍要求两位独立人类读者，模型意见可以辅助修订。未知作者来源或未知评审身份不能取得独立评审资格。

系统可以强制这些已登记约束，但无法从一个 ID 或布尔值证明真实人身份。报告区分“已拒绝身份冲突”“提交人担保”“可核验交付/执行记录”，不把自述升格为系统证明；不新增一套实名认证设施。

协调者保存映射；评审者只取得匿名 export，不能访问完整仓库、生成日志或协调者 mapping。盲 token 每轮重新分配，旧 BR-73 等已公开身份不可作为新盲性依据。匿名包标准化与正文保真规则预先声明；用已实际交付的 packet SHA 绑定意见。读完收集身份知晓/猜测，标记已解盲或被污染的阅读，不掩盖。

至少两位评审者分别阅读同一候选集，在沟通前提交。不得把同一人两个 ID、同模型两会话或同意见两份副本算作两人。分歧保留；TIE/NEITHER/全部淘汰均是合法结果。裁定者在解盲后解释取舍，不能因流程期待赢家而强制排序第一成为稳定正文。

旧第 86 回、P7 意见按历史/自述来源导入，保持原文和结论；独立性、版本和实际输入无法补证的部分进入新一轮重评，不自动继承正式资格。

## 6. 让路线与流程分别发生竞争

### 6.1 路线定义

每回至少两个有效、真正不同的复原路线，除共同硬边界外，记录各自的因果链、行动决策、信息分配、物件路径和下回影响。只改压缩程度、措辞、分段或视角而未改变情节决策，归为同路线修订。

第 86 回可研究的差异应发生在未被证据锁死的环节，例如求医/跑腿安排由谁决定、宝玉为何来迟、紫鹃如何判断等待、他人何时得知病变及其后果。死亡/冷药等当前方案硬约束保持；任何“另一路线”仍必须说明所选复原前提与 OPEN 范围。上述是试验设计问题，不是已有证据支持这些具体事件。

路线结构差异用 Decision / plan 差异与下一回状态差异展示，编辑确认是真正不同方案；不以人工 `different_route: true` 作为机器证明。复用已有四个 scenario 中可合法映射到共同任务的选择，不硬套不同 probe 排名来证明某路线更好。

### 6.2 直接写作与新旧流程对照

路线比较与 Harness 效果是两个因素。先做同一约束/路线下的流程对照，避免把更好的情节恰好分给新 Harness。

| 组别 | 输入与控制 | 所测内容 |
|---|---|---|
| 直接写作 | 相同冻结材料、任务、约束和作者预算；没有 Harness 检索编排和迭代反馈 | 设施是否改善普通直接成文。 |
| 旧流程 | 相同任务；原 lint、原上下文组织与修订方式 | 与已有流程比较。 |
| 改进流程 | 相同任务；语义反馈、经审范例和结构化修订 | 检查改进后的设施效果。 |

三个流程使用同一作者模型/设置；记录 tokens、调用、检索、编辑时间和评审成本。先声明预算上限与差异，不能新组多用修订轮次却称同预算获胜。直接组先冻结，随后对三组运行相同评估；评估反馈不得回流直接组，影响原对照定义。采用候选可以另开后续修订版本。

路线实验另比较至少两条路线；每回还保留一个直接写作基线。三回试点可逐步完成，不要求一次运行巨大的全因子实验。所有候选共享实际可用的来源约束，直接写作不代表放弃证据边界。

### 6.3 阅读协议

每个候选至少两位独立读者。候选数少时做匿名全排序，或做覆盖所有候选的成对偏好；展示平局与分歧，避免仅用 PASS/FAIL。完整三回也按整段阅读，而不只拆成单回打分。

维度沿用 scene cohesion、character voice、life detail、engineering feel，再用具体句段支持意见；回目、回末和跨回效果作为同一文学/阅读类别的分项。关注“哪份更值得读、人物行动是否成立、哪次修订真的改善”，不以禁词数量或流程通过数代替。

输出匿名原意见、排序/偏好投影、各路线事件差异、错误与成本、编辑采用理由。小样本只支持本试点选择；后续扩张前再积累任务和读者。

## 7. 连续三回与语料先行的小范围试点

建议首个研究试点选择 **85–87 回**，直接覆盖本次第 86 回漏洞、紫鹃声口与死亡后的连续影响；它是新研究任务，不改选定 production 队列，也不把 86/89/92 当连续三回。

先从选定复原状态建立 85 回入口、共同来源和下回边界，再补三回实际使用的 scene contracts。每条路线贯穿三回；逐回记录人物知情、物件与资源出口，保证前回出口为下回入口。现有材料不够时保留待完成，不能用空 `exit_state: []` 表示连续性通过。

语料工作在语义接口开发期间并行做有限范围：

- 对试点实际检索的正文和声口例句逐段核对原页、上下文、正文/脂批身份及说话者，保存修改前后定位和审计意见。
- 用已有 corpus audit 协议按章、层、字体边界、黑色脂批、变体与附录做分层抽样；重点审 162 条未知见证及实际使用的未对齐材料，不要求把所有 7,497 条强行精确匹配。
- 区分编辑材料本不应有 EPUB 对应、版本差异、切分差异、多义命中、字形缺口和实际误分类，分别计数。未知脂批见证不能作为某本的承重证据。
- 范例检索明确分层与审计状态；候选层允许研究探索，正式使用只采用已审范围。检索评分不提升来源权威。

当前 production admission 仍要求既有来源/语料审计与 P9 实际提交。研究试点可以在研究权限下准备和比较，但不能因为只审了几条范例就宣称全 dataset 通过，或跳过现有全局门禁。若未来正式采用只依赖经审子集，需在既有 declared-input scope 中显式选择该子集并做闭包核验。

试点完成条件：三回正文和至少两条路线存在；每回都有直接写作对照和两位有效独立意见；没有未解决硬性语义冲突；85→86→87 知情、物件和状态可追踪；一轮实质修订与重评完成；采用理由和未决范围明确。发布仍按既有 publication 权限与闭包处理。

## 8. 文体与人物声口

优先整合十八份现有 voice profiles 与六份 knowledge profiles，声明各自来源、覆盖和是否稀疏；把 `voice_profile_hooks` 解析到实际 profile，缺档明确报覆盖缺口。先处理紫鹃的 World 绑定与试点实际出场人物，之后按出场重量补齐其他人物。

声口范例至少包含实际对白、对象关系、压力情境、所属原文和定位。诊断称谓是否符合身份/亲疏、人物是否突然全知或说教、不同情境中的语气是否可信。遮名比较、引用例句和编辑判断比一个“wit: high”分数更有用；稀疏人物允许 abstain。

回目与诗词设独立的文学诊断轨，复用已存在的 poetry screen / blind 接口。先做字数、结构、重复与人物/事件对应；语义对仗、章回命名功能、诗词声口及必要格律交给有语料依据的判读。原有确切回目文字锁仍作字节约束。说书口吻与称谓分布只作分项观察，不能要求每回固定出现“且说/话说”来迎合指标。

这些指标使用经审前八十回作为分布参照，按叙述、对白、回目和诗词分层；不在未审 corpus 上拟合“正宗声口”阈值，也不把二十八人都填满当作文学覆盖完成。

## 10. 最后的结构整理

先按领域迁移代码，保持已有公共命令兼容：application 下拆 parser 注册与 handler；`evaluation/` 接收 scene lint、semantic checks、literary diagnostics；`review/` 复用 packet 与提交验证；competition/adoption 调用公共结果服务。人物知识、世界状态和物件留在各自领域；证据图不并入评估器。

数据路径按完整设计的稳定领域整合单文件目录，使用 owner/显式引用切换与回归检查；不可变正文、原评审、manifest 不因换目录重新授予权威。历史 ID 保留可追溯映射，新文件避免再用 P6/P7/R4 当职责名称。

将现行 `SourceClosureMigration` 重命名为表达“载体/定位改绑”的领域服务，澄清 ADR 0002；只有确认无消费者的旧导入器才删除。声口与场景状态数据先统一职责，再合并目录，不能只移动两个 YAML 就宣称世界模型统一。

减重先移除可重导出的未登记交付副本，保留内容清单和重建命令；已登记不可变包遵守现有跨版本资产规则。LFS/release 方案须配套物化下载、SHA 核验和离线发布包，避免 clone 后只得到指针或断链。暂不重写 Git 历史。

许可交付是一份供所有者决定的 code/data/derivative text 分项提案与材料清单；决定前维持 README 当前许可状态，不自行补 MIT 等授权。
