# 全书规划与场景契约 v1

状态：领域契约已定义；完整规划与写作服务待实施。

## 版本与世界

- ReconstructionBranch 由共同基线、选定假说和事件增量构成；Git 分支与复原分支分开。
- 世界事实带 branch/version 范围；人物知识区分所知、推测和误判。
- `data/project/scope.json` 声明章回范围；81—100 是当前项目配置，不是原稿篇幅的证据断言。
- 物件网络的查询、默认章回和转移范围使用该配置；基线章回在物件记录中声明且早于项目首回。终局、身份 OPEN 与接济等已有模型检查点仍独立校验，范围调整不能静默跳过它们。
- 历史机制记录时代、地域、身份、制度条件与例外，仅在适用范围内支持可行性。

## 已实现的方案版本约束

`data/project/current.json` 的 `owners.plan_constraints` 选择约束记录，`plan_constraints_binding` 绑定其 ID 与规范化 JSON 摘要。初始版本为 `data/project/plan_constraints_v1.json`，承接现行 Reconstruction、World 与 Literary Ecology 的 17 条具体方案约束：玉物流和羁押模型、两个冬季排程、九个世界状态检查点、四项文学选择。

每项约束包含唯一 ID、类型明确的查询路径、期望值和资产出处；记录绑定所选发布基线，加载时核验来源资产字节。领域校验对实时状态执行这些约束；缺失目标、版本摘要漂移、重复规则、缺失出处或基线错绑均失败。世界回放按项目声明的章回范围执行，外层知识不得泄漏至人物世界。

初始记录是 `EXISTING_BASELINE_MIGRATION`，继承已有保护，不补写历史人工审批。替代版本可以用 `PROPOSED_REVISION` 表示待审方案，并在隔离工作副本中显式选择、验证。选择记录和刷新摘要都不构成文学采纳；其权限始终是 `CURRENT_IMPLEMENTATION_ONLY`。正式采用仍须有对应版本的有效评审，并通过现有竞争、P-Lock 与发布门禁。统一方案审批及失效传播服务仍待实现。

已确认的证据锚点、OPEN 边界和真实评审继续由各自契约检查；约束文件不能覆盖这些权限。

## 四个尺度

BookPlan 包括全书人物线和关系发展；跨回计划包括因果、资源、伏笔和信息传播；ChapterPlan 包括场景顺序、线索交织、叙事重量和回末作用；SceneContract 包括行动、人物、物件、前置和退出状态。

事件发生时间与读者获知顺序分别记录。未回应事项形成编辑任务，但不强制机械闭合所有线索。

## ScenePacket

写作包固定：branch/version、章回场景目标、证据边界、已选假说、世界/人物知识/物件状态、关系变化、章回功能、叙述计划、范例版本、前后文、未完成事项、输出协议。

研究 OPEN 不要求正文故作含混；当前方案可以作出明确安排，并在研究或注释记录中标明复原选择。

## 修订传播

来源变更重审解释；假说改选重算事件状态；结构变更重审信息释放；局部润色检查有限范围。系统输出影响链、必须修订项、人工核查项和不受影响项。

首个生产闭环以现有 Ch89 候选为主，并用另一类场景验证泛化；真实门禁按既有状态执行。

## 生活与文化

人物从自己的知识、推测、误判、传闻或感知行动和发言。诗、医药、礼俗、宗教、器物与艺术须承担人物行动、冲突或场景质感；不设置每章文化元素的配额。日常劳动、物质条件、信息差和次要人物的约束按场景需要进入设计。

## 已实现的人物知识与声口接口

场景知识显式区分 `knows`、`believes`、`suspects`、`does_not_know`；没有出现在所知集合中不自动等于“不知道”。事件检查点更新知识，避免人物提前知道死亡、门禁规则或全案信息。SceneContract 的 `knowledge_checkpoint`、`knowledge_guards`、`voice_profile_hooks` 将知识与声口约束交给普通场景评估器。

对话与行动中的越权知识由合同声明的守卫检查；这不是通用自然语言读心能力。声口 hook 使用有出处的特征、关系变化及禁止漂移，只能报告匹配与冲突，不能自动确认作者或说话人身份。缺少可靠声口资料时使用 `SPARSE_ABSTAIN`，如当前茜雪 profile。

## 已实现的预写作接口与计划映射

预写作使用 `IMPORTED_AUDITED_PROFILE` 模式，接收已有前八十回生态审计；语料重新抽取与自动建立新基线仍待实现。缺口状态为 `SUFFICIENT`、`THIN`、`MISSING`、`NOT_APPLICABLE`，维度由数据声明，章回覆盖来自项目 scope。

当前 v5.2 预写作依赖顺序为 `33 → 34 → 35 → 40 → 39 → 38 → 37 → 36 → 41 → 42`。先恢复事件形成与社会过程，再处理人物生活、文本身份和韵文；该顺序属于当前工作计划。
