# ADR 0005：写作输入、历史谱系与当前准入分离

状态：已实施。新写作默认使用 writing renderer v2；v1 仅用于读取和验证原协议。

## 问题

v1 把 `data/project`、世界／知识／物件目录和来源 YAML 分片整体绑定到每份写作请求。读取会话稿还要求用当前工作树重新渲染出相同请求。因此治理配置、无关记录、目录新增文件乃至实现调整，都会使真实历史稿无法读取、比较、反馈或继续修订。2026-10-20 的隔离复现中，只给闭包根配置追加一个换行，当前 81–100 回的 20 份请求全部失效。

这将三个不同问题混为一谈：当时究竟保存了哪些输入和输出、这些输入是否与当前选择相容、当前是否满足研究或生产准入。

## 决定

1. **历史字节保管**。导入会话稿和执行 provider 请求时，把输入、模板以及原始导入文本／请求的字节写入 `artifacts/writing-inputs/blobs/<sha256>.bin`，以不可覆盖的清单绑定原路径、原摘要和 blob。相同内容复用同一 blob。原路径只表达当时的逻辑身份，不是历史读取的内容回退。
2. **版本化依赖选择**。v2 显式绑定写作包、所选计划和场景、实际入口运行时输入、范例和本地材料的传递依赖。Source／Claim 按所选记录内容绑定，不绑定承载其他记录的整个分片；Asset 只绑定内容身份和派生关系，不绑定目录分片、发现索引或登记用途等治理元数据。模板、前文和编辑备注仍按实际字节绑定。新增的实际场景或传递引用会被重新渲染比较发现，不能通过漏列输入获得相容判定。
3. **实时治理在提示词之外**。生产审核状态作为准备时观察记录保存，不能授予资格，不进入 v2 作者提示词。闭包配置、审核 selection、交付及实施进度由当前项目验收独立检查。
4. **两种验证入口**。准备／导入仍校验新请求与所选输入的当前渲染结果，防止丢依赖或重算哈希伪造上下文。已登记草稿的读取只验证冻结请求、快照、正文、作者及修订关系，不执行当前渲染器。`write check --current` 另报告当前写作输入相容性；`--production` 再单独计算章回生产准入。
5. **修订保留父稿依据**。新修订显式引用父稿、父稿正文、反馈、备注和新模板，不把祖先的全部全局输入平铺进新清单。父稿及反馈关系仍完整验证。当前输入已经变化时允许保留旧依据做研究修订，但相容性报告必须显示过期，研究发布的 `CURRENT_WRITING_INPUTS` 门控阻止按当前依据采用它。切换写作包须另开明确的新起草请求。
6. **旧协议迁移不改历史**。`write freeze-history` 先通过原 v1 的完整当前校验，再追加历史快照与 v2 相容性基准到 `data/writing/history/`。不重写正文、prepared request、run、draft、作者、父稿、意见或发布选择。已经失配的旧记录拒绝迁移；应先在具备可核实原字节的历史检出中校验，不能把现行字节冒充旧输入。没有迁移记录的 v1 保留原检查行为。

## 不变量与边界

- 历史校验通过不能替代当前来源、语料、合同、人工审核或发布准入。
- blob、清单、请求、正文或作者绑定被篡改仍失败；快照缺项、多项和不安全路径也失败。
- 当前输入过期只改变当前相容性，不抹除真实历史。无关治理或无关来源记录变化不改变 v2 写作依据。
- 冻结的提示词及其校验并不能证明会话模型实际读取了输入；会话模型、隔离和资源仍是原有未核实声明。
- 这是按实际文件与所选记录切分的第一版。写作包若显式绑定一份跨多回的世界文件，该文件的整体版本仍属于该包的输入；进一步按世界事件投影分片须另行版本化，不能静默改变现有依据。

## 验证

回归覆盖治理变更、旧输入退休、所选输入变化、新依赖、provider／会话路径、快照去重和篡改、历史迁移、反馈与连续修订，以及历史有效但当前过期时的发布拒绝。实际 20 回使用 `tools/verify_writing_lineage.py` 验证，迁移记录与隔离验收报告随仓库保存。

- [20 回历史与当前相容性验收](../../artifacts/migration/writing-custody-20261020/verification.json)：全部历史 PASS、当前 CURRENT。
- [隔离变更实验](../../artifacts/migration/writing-custody-20261020/governance-regression.json)：闭包配置追加换行，20 回均保持 CURRENT；只改第 81 回计划，仅该回 STALE，20 回历史仍全部 PASS；81 份原始关联记录字节未改。

2026-10-20 在 Python 3.12.13、文件与工作区逐字节相同的隔离检出中运行全量测试：1729 通过、1 项跳过。`rcwh validate`、物理资产校验和 `declared-inputs-regression --require-tracked` 均通过；当前工作区的 20 回冻结历史也直接读取验证通过。这些结果只验收代码与输入保管，不改变独立来源审核和生产准入状态。
