# ADR 0008：审阅输入保管与复审闭环

状态：已实现；继承 ADR 0004–0007。仅研究轨道。

## 输入范围与历史

新登记记录附 `input_snapshot`，在内容寻址的 manifest 和 blobs 中保存原意见真正引用的 packet、所审 subjects、显式 context、样本和来源载体字节。验证意见只读取其结果对应的 subjects，未分派材料不进入这份意见的保管范围。历史记录验证快照；`current_compatibility` 另查当前路径，过期不冒充历史损坏。快照、原意见或回执损坏仍是完整性失败，不能继续登记。

旧记录没有快照时继续按旧方式检查当前路径，不能凭空补出已丢失的历史字节。本次真实仓库尚无正式意见，不需要推测或迁移旧意见。

prepare 为每回生成内容寻址的独立 packet，显式绑定本回候选稿、写作包、政策；来源从 YAML 提取单条完整记录形成独立产品，发布时仍与当前 provenance source 精确比较。改另一回或另一个来源不会改变这些输入。旧 packet、request 快照和 v1/v2 计划保留；当前 request 改用 v3，正文、草稿、作者回执不变。

旧包的正面或未读意见保留，但不计新包两位读者，也不单独造成 PENDING。同字节、同适用上下文的 BLOCKING 负面继续生效，不能换 packet 隐藏。显式章回 context 真正改变时，旧意见列入 `prior_context_opinions`，不计当前门控；协调者仍须考虑并有理由处置其中异议。发布核对 context 恰是所选候选稿、写作包和政策，不能靠任意上下文声明解除异议。没有显式旧 context 的记录不自动判为不适用。

## 真实补读与故障恢复

直接登记和 campaign 登记均按 `supersedes` 链的唯一有效末端恢复。仍保管并验证被替代的原始输出，不删除异议，也不把两个未互相替代的冲突输出任选其一。

`review-status` 的 COMPLETE 仅表示收到意见，`needs_followup` 标出 NOT_CHECKED/PENDING/UNVERIFIED。用 `review-reopen PLAN JOB --reason ...` 请求真实补读：保留原轮次，分派新会话，骨架携带原记录的 supersedes。复用的旧阅读也可重开。修正永久故障或处理耗尽后同样可显式重开；活跃任务不能重开。每轮临时故障仍至多三次，退避 5、10 秒，不自动无限重试。

`review-fail` 必须携带分派的 `--assignment-sha256`。同一次失败重复送达为幂等操作；其他迟到或未知尝试不得修改当前重试。未变 packet 中满足覆盖、样本和独立身份要求的两份完整意见可供新计划复用，状态逐项列出实际记录；不会伪造新的执行或意见。

## 来源与裁决

SOURCE 分派包含单条原始记录、与固定提取产品逐字比较的引文及上下文，以及对应 PDF 原页或保留的原件图像。图片单独列在 `inspect_images`；每项最多四图、合计 6 MiB，文字仍最多 197 KiB，两个预算分别报告，不将图像字节当作文字 token。图片样本逐项要求两位读者检查。不能查看图片或看不清时必须 NOT_CHECKED，不能从 hash 相等推断转录正确。

PDF 图像按固定参数从绑定的原载体生成，当前登记与准入时重算；历史完整性验证所存载体、图像和回执字节，不依赖后来版本的图像编码器重放。代理目读校录仍保留其资格限制，来源阅读不等于独立人工资格。SOURCE 使用专门指令；文字或图片超预算按完整来源重新分组，不截断引文后声称已读完。

协调者决定涵盖候选稿、包、合同、依赖来源和语料的全部当前意见，以及明确变更上下文的旧异议；每条负面意见必须有理由裁决。新增任何相关意见都会使旧决定待更新。BOOK 仍为 ADVISORY，不增加发布门。

## 暂存与发布

PENDING 仅写入 `releases/agent/.pending/<edition>/<revision>/manifest.json`，不占用正式 edition。相同待审快照重复构建为幂等操作；审阅通过后仍可使用原 edition 发布到 `releases/agent/<edition>/`。正式目录继续拒绝覆盖，stable/ACTIVE 不变。每次 build 的两轮评估各自重新核验记录与输入；只在单轮内部复用重复的 packet 检查。

回归覆盖：来源备注变更后的历史完整性、旧 PASS 换包、旧负面保留、直接复审替代链、NOT_CHECKED 补读、故障轮次身份、未变材料复用、拆分合同异议裁决，以及 PENDING 后同 ID 正式发布。
